# Архитектура Clive: Структура модулей

## Модуль `ui`
Отвечает за интеграцию с нативным UI, предоставляет точки входа для экранов.

### `CliveScreen`
**Главная точка входа** во всю технологию Clive.
- **Ключевой метод:** `bind()` — устанавливает данные экрана и условия для `Clive` (например, диапазон версий манифестов).
- Инкапсулирует логику взаимодействия с `Clive` и host swap `Clive`-инстансов.

### `CliveLayout`
Точка входа в рендеринг конкретного модуля, получаемая через вызов `cliveScreen.layout(moduleId)`.
- Является основным источником данных для рендеринга лейаутов.
- Скрывает за собой детали реализации, включая hot swap `Clive`-инстансов, критические ошибки инфраструктуры (падение `Zipline/Treehouse`), предоставляя стабильный интерфейс для UI.

## Модуль `configuration`
Управление конфигурацией и условиями работы `Clive`.

### `CliveCondition`
- Определяет условия, по которым выбирается `Clive`-инстанс для экрана (например, диапазон версий манифеста).

### `CliveBaseUrlProvider`
- Провайдер для передачи `baseUrl` манифестов (и модулей) извне.

---

## Модуль `core`
Ядро технологии, содержащее логику работы с `Treehouse/Zipline`, динамическими модулями и т.д.

### `Clive`
Основной класс, инкапсулирующий логику работы с **Treehouse/Zipline**.
- Предоставляет наружу `Flow<Clive.LayoutState>`, позволяя подписчикам отслеживать доступность конкретных модулей.
- Отвечает за тихую (фоновую) подгрузку модулей.
- В случае критических ошибок `Zipline/Treehouse`, `Flow` эмитит состояние `LayoutState.Error` для всех пользователей.
- Для перезагрузки из-за ошибки или обновления данных - `clive.update(data)`.

### `CliveRepository`
- Управляет жизненным циклом `Clive`-инстансов: выдает необходимый `Clive` (на основе `CliveCondition`) или уничтожает неиспользуемые экземпляры для освобождения ресурсов.

## Модуль `logger`
Централизованная система логирования.

### `CliveLogger`
- Единая точка сбора всех внутренних логов технологии `Clive`.

---

## Модуль `manifest`
Работа с манифестами.

### `CliveManifest`
- Обертка над манифестами `Treehouse` со вспомогательными метод-хелперами для парсинга и валидации.

### `CliveManifestRepository`
- Точка входа для получения манифестов.
- Инкапсулирует источники данных: сетевые запросы, персистентное хранилище.

---

## Модуль `module`
Работа с модулями.

### `CliveModuleRepository`
- Точка входа для получения модулей.
- Инкапсулирует источники данных: сетевые запросы, персистентное хранилище.

---

## Модуль `treehouse`
Низкоуровневая интеграция с фреймворком `Treehouse`.

### `BindReuseRoot`
- Связывает `ReuseRootView` с `CliveScreen`, передавая `UiConfiguration` и другие зависимости.
> **ВАЖНО** Текущая реализация является временным решением. Поскольку экземпляр `Clive` шарится между экранами, возникают сложности с управлением ЖЦ ReuseRootView. Нужно обсуждаться как избавиться от этих проблем.

### `CliveTreehouseFactory`
- Фабричный класс для создания инстансов `Treehouse`.

### `CliveTreehouseHttpClient`
- Кастомный HTTP-клиент из-за отсутствие доступа к внутренней реализации загрузки модулей и манифестов для `Zipline` внутри `Treehouse`.
- Перенаправляет запросы `manifest`/`module` в локальные `Repository`. Это позволяет контролировать кэширование и логику загрузки.

### `CliveZipline`
- Обертка над `Zipline`.
- Позволяет осуществлять догрузку модулей непосредственно во время выполнения.
